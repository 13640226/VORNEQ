1. Purpose and Product Scope

VORNEQ AI is a multilingual general-purpose AI assistant offering Free and Premium subscriptions in Persian, German and English.

In scope

  • Secure conversations and history
  • File analysis
  • Central AI Gateway and model routing
  • Usage metering, quotas, cost accounting
  • Subscription lifecycle and billing
  • Monitoring and abuse prevention

Out of scope for V1

Autonomous external writes, unrestricted browsing, voice and image generation, unlimited usage, automatic security approval, and unauthorized production changes.

3. Subscription Plans

Free — €0/month

30 messages/day · 3 files/month · 5 MB/file · Economy model · 30-day history target · 1 concurrent request · €0.75/month hard AI budget · No advanced model or web search.

Premium — €12.90/month

VAT-inclusive where applicable · 150 messages/day · 50 files/month · 20 MB/file · Economy + metered Advanced · Long-term history subject to policy · 3 concurrent requests · €5/month hard AI budget · Web search deferred.

Limits are versioned configuration. Message counts do not override token, financial or security limits. Disclose material limitations before purchase.

4. Data Model

Logical design only; no database creation is authorized.

1. SubscriptionPlan — LOGICAL

Fields: id code (FREE/PREMIUM) display_name price_minor_units currency billing_interval tax_behavior active policy_version created_at updated_at

Constraints: Unique active code/version; integer minor units or exact decimal; never float money.

2. UserSubscription — LOGICAL

Fields: id user_id tenant_id plan_id status provider provider_customer_id provider_subscription_id current_period_start current_period_end cancel_at_period_end created_at updated_at

Constraints: Statuses INCOMPLETE, TRIALING, ACTIVE, PAST_DUE, CANCELED, EXPIRED, SUSPENDED. Verified provider state required for Premium; client plan name is not proof.

3. AIConversation — LOGICAL

Fields: id owner_user_id tenant_id title status created_at updated_at deleted_at retention_expires_at

Constraints: Owner and tenant checks on every read/write.

4. AIMessage — LOGICAL

Fields: id conversation_id role content_reference model_identifier request_id created_at safety_status

Constraints: Validate roles; user content cannot become privileged system instruction.

5. AIUsageLedger — LOGICAL

Fields: id user_id tenant_id subscription_id request_id model_identifier input_tokens output_tokens cached_input_tokens provider_cost_minor_units currency pricing_version usage_date created_at

Constraints: Append-only or tamper-evident; unique request ID, idempotent ingestion, tenant isolation and provider reconciliation.

6. QuotaReservation — LOGICAL

Fields: id user_id tenant_id request_id quota_period reserved_tokens reserved_cost_minor_units status expires_at created_at settled_at

Constraints: Statuses RESERVED, SETTLED, RELEASED, EXPIRED, RECONCILIATION_REQUIRED. Atomic reservations.

7. BillingEvent — LOGICAL

Fields: id provider provider_event_id event_type signature_verified processing_status received_at processed_at

Constraints: Unique provider event ID within provider namespace.

8. AIFile — LOGICAL

Fields: id owner_user_id tenant_id conversation_id storage_reference original_filename content_type size_bytes scan_status processing_status created_at retention_expires_at

Constraints: Private by default; filename is never a trusted path.

5. AI Gateway Contract

Logical endpoint: POST /api/ai/v1/chat. Server determines effective model, entitlement and maximum cost; client cannot authorize them.

Processing sequence

  1. Authenticate user
  2. Resolve tenant context
  3. Verify conversation and file ownership
  4. Resolve subscription entitlement
  5. Apply abuse, rate and concurrency controls
  6. Estimate maximum request cost
  7. Atomically reserve quota
  8. Select approved model
  9. Construct provider request using server-owned credentials
  10. Execute with bounded timeout, output and retries
  11. Record usage and reconcile reservation
  12. Return authorized response

Fail closed: unknown tenant, invalid entitlement, unavailable quota service, unknown pricing, missing credentials, unauthorized resources, unbounded cost, unsupported files or security-control failure. No fallback bypasses these checks.

6. Model Routing

Economy

Default for Free and ordinary chat, translation, summarization and simple coding.

Advanced

Only for verified Premium entitlements with enabled feature, remaining allocation and passing cost/security checks.

Versioned model registry

Provider, model, capabilities, input/output limits, current prices, currency, availability, approved data policy, timeout and retry policy. No hardcoded provider pricing in business logic.

7. Quota and Usage Enforcement

Three independent server-side controls: message count, token allowance and financial budget. UTC enforcement periods with localized presentation. Atomic reservations prevent races. Failed or uncertain provider usage must be released only when proven unbilled, otherwise reconciled; uncertainty cannot grant unlimited additional allowance.

8. Billing and Payments

Provider such as Stripe may be evaluated; no provider selected by this contract. Required: hosted checkout, subscription renewal/cancellation, failed payments, refunds, billing portal, tax-aware invoices, verified webhooks.

Never store raw card data/CVV. Verify webhook signature on raw payload, deduplicate events, tolerate out-of-order delivery, reconcile authoritative subscription state. Browser redirects cannot grant Premium. Grace periods, proration, refunds and downgrade rules require explicit policies.

10. Security and Privacy

  • Authentication and service-level tenant authorization on every access
  • Private conversations and file storage; encryption in transit and at rest
  • Server-managed secrets, no API keys in browser or logs
  • Input/output size limits and prompt-injection boundaries
  • File-type validation and malware scanning
  • Abuse detection and rate limits
  • Retention, deletion and lawful-processing controls
  • Provider processing and international transfer review
  • Minimal sensitive logging and auditable admin access
  • Safe errors without secret disclosure

Uploaded content is untrusted. AI output is not security approval. Future agentic write actions need a separate authorization contract.
